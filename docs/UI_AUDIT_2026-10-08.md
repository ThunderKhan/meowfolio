# Meowfolio UI & UX audit — 8 October 2026

Scope: the publicly reachable welcome, scrapbook, saved-for-later, cat detail and history, full-photo viewer, all scan stages, local-profile editor, and same-tab Story Studio. The developer-only Matching Lab is noted separately. The audit reviewed React, CSS, design/UX/accessibility guidelines and production/Chromium tests. Responsive visual screenshots are produced by the browser suite at 390×844 and 1280×900.

## Findings & corrections

| Area | Finding | Corrective action |
| --- | --- | --- |
| Shared typography | Nearly every surface used heavy Courier and very tight headline tracking; paragraphs, metadata and headings competed for attention. | Body copy uses a system sans stack; pixel/window headings and action chrome retain monospace. More comfortable headline leading and smaller tracking. |
| Color contrast | The previous primary gradient began at `#ef65ad`, offering inadequate contrast against white labels; pink highlight text was also too pale on light surfaces. | Darker accessible gradient (`#c13577` to `#a91f68`) and stronger scan-label ink. |
| Shared controls | Global input rules overrode radios, sliders and checkboxes; CSS accumulated ad-hoc escaped utility selectors that produced CSS-optimizer warnings. | Target textual inputs only, let native/select controls work, remove fragile hand-escaped class overrides, and add logical focus states. |
| Welcome | Strong checkerboard and decorative chrome distracted from the two real actions; mobile CTAs could appear stacked. | Soften patterned backdrop, prioritize readable headline and two-column mobile actions, simplify storage copy. |
| Empty scrapbook | Button duplication and tiny captions made the first impression busy. | Keep one primary capture area on small screens; strengthen explanatory type, adjust footer and use less decoration. |
| Collection | Cat images could appear clipped; date/name labeling was disproportionately small. | Show full saved photo within thumbnail mat and increase readable metadata. Keep consistent card heights and tap areas. |
| Cat detail | Heavy labels, irregular hierarchy, photo crop, technical metadata; navigation crowded at small widths. | Use consistent text and action treatment, full-photo viewer and clearer lower-priority content. |
| Encounter log | Image thumbnail cropping and badges competed with encounter date/note. | Full-photo fit with optional zoom viewer; standardize accent and notes. Location remains collapsed. |
| Saved-for-later | Long technical copy, small cards and vertically stacked buttons. | Plain-language microcopy, full-photo preview, responsive row actions for Process/Delete. |
| Scan / photo selection | Mismatched buttons and header colors between states; small labels and technical wording. | Shared action-row grid, consistent button hierarchy, less internal jargon, dark readable accent. Camera/gallery/find actions retained. |
| Scan / consent and progress | User-facing text mentioned technical internals and a weak hierarchy. | Explain device processing and data use plainly; consistent text/button treatment without changing consent behavior. |
| Scan / multi-cat and identity | Photo viewing forced another cover crop and used different heading rhythm. | Make display-only photos fit, preserve human identity decision and explicit controls. |
| Scan / name, note, location | Mixed form styles and CSS-specificity conflicts could make contrast inconsistent. | Fix input selectors and form readability, keep optional location explicitly opt-in and details separate. |
| Scan / save, error and success | Engineering terms such as “embedding” and “transaction committed” appeared in ordinary user copy. | Replace with specific human-readable outcome and recovery text; keep real save/error transaction logic. |
| Local profile | Too much reassurance repeated and form actions wrapped irregularly. | Shorter explanation and consistent two-button form action grid; no misleading claim of online accounts. |
| Story Studio | Theme/framing/export controls used different densities, a redundant Close button and tiny status labels. | Consistent type, clean two-action export row, avoid duplicate close navigation, main page heading and route focus. |
| Full-photo viewer | Modal failed to move/restore focus and pinch had no keyboard-accessible equivalent. | Focus management, tab containment, body-scroll lock, on-screen zoom +/- controls, reset, and Escape dismissal. |
| Browser navigation | Closing Studio pushed another history entry; pressing Back could reopen the Studio. | Return through browser history for in-app entry; replace route for direct Studio opens. |
| Reduced motion | Global rule disabled *all* CSS transforms, including functional zoom/pan. | Disable decorative animation only; preserve required photo transforms. |

## Design rules maintained

- Local-first: photos stay in browser IndexedDB and are not uploaded for inference or story export.
- Colorful pink Y2K scrapbook identity, but prioritize photography and readable type.
- Full original photo over forced crops where the photo is a memory.
- Two-column action group when there is sufficient width; no unintentional vertical button pileups.
- Accessible keyboard focus, real button labels and 44–48px important targets.
- No changes to AI release gate, consent policy or saved-cat record format.

## Verification

- `npm run typecheck`, `npm test`, `npm run build`, production artifact audit.
- Playwright production smoke and mock/real-model browser suites.
- Browser-generated visual audit screenshots of onboarding, empty state, local profile, populated collection, cat detail and Studio on mobile/desktop.
- Real Android pinching, screen reader, large-text mode and Vercel deployment still require device checks; Chromium green is not physical-device proof.

## Exclusions / future improvement ideas

The Matching Lab is a developer/evaluation-only route; its technical labels are intentional and not shown in public builds. Backup/export and authenticated cloud accounts are separate product decisions and have not been added. Browser local storage can be evicted, so UI copy must not promise permanent storage.
