The complete journey

The scope defined the loop. This draft specifies the download boundary, human identity choices, explicit save, and what survives a failure.

Explore the surfaces

Expand each section for behavior, states, and observable checks. F1–F7 match the stable headings in the Markdown PRD.

F1Welcome, collection entry, and photo preview

One welcome with Start my Meowfolio. Explain on-device AI, noticeable first-download time/data, and optional location. Then Spot a cat leads to capture or photo selection and a replaceable preview.

Boundary: no account, notification prompt, location prompt, tutorial carousel, or model download before scanning.

Check
  • Preview can be reached and replaced before expensive processing.
  • Opening the scrapbook does not require models.
  • Find the cat uses the selected photo.
F2Preparation and processing

If model files are missing, explain the download and possible cache reuse. The photo stays on-device. Download models & continue starts downloading and changes the same screen into progress/status.

States: go back before consenting without losing the photo; ready models skip consent; lost cached files require consent again. Preparation failure offers retry or return to collection, retaining the photo for retry.

Check
  • No model download before explicit authorization.
  • No invented download size, progress, or permanent-cache promise.
  • Prepared models continue the selected photo into local detection.
  • Interface remains responsive; practical fallback must be validated.
F3Detected subject selection

One detected cat uses that crop. Several detected cats show selectable crops. No cat found shows the original photo and a way to try another.

Check
  • Multiple-cat photos wait for a subject choice.
  • Only the selected cat feeds the comparison.
  • No-cat results do not allow a save-as-cat bypass.
F4Identity decision and existing-cat picker

Empty scrapbook: This looks like a new cat
Show the detected crop and Name this cat. Optionally explain that there are no saved cats to compare with yet. Detection and embedding still run; skip saved-cat comparison. No familiar-face language, No match found message, or existing-cat action.

Possible familiar face
When a saved candidate exists: This cat looks visually similar to Mochi. Is it the same cat?

Show the new crop beside the saved cover photo, name, and Met N times. Actions: Yes, it’s Mochi; No, this is a new cat; Choose another saved cat.

No familiar cat suggested applies when saved cats exist but no useful suggestion is available. Offer Choose an existing cat or Add as a new cat. The picker uses photos, names, and counts, followed by confirmation.

Check
  • No raw similarity score or fake probability.
  • Manual selection works even when AI misses.
  • Choosing identity does not save automatically.
  • The first cat gets a welcoming naming path, not a failed-match state.
F5Encounter save, location, recovery, and success

Keep the photo, selected identity, and automatic timestamp. New cats need a manually entered name. Note and location are optional. Notes belong to encounters only.

Location failure: “Location wasn’t added. You can still save this encounter.” A slow request offers Save without location.

Save failure: “We couldn’t save this encounter. Your details are still here.” Preserve the full pending encounter and offer Try saving again or deliberate Back/Cancel.

Success: “Mochi is in your Meowfolio.” or “Another Mochi encounter saved.” Then View Mochi or Back to collection.

Check
  • No location prompt without the explicit add-location action.
  • Location failure never prevents saving the encounter.
  • No success until the local write completes.
  • Retry creates no duplicate cat or encounter; details remain after failure.
F6Collection and cat detail

Image-first cards show cover photo, name, Met N times, and a quiet last-seen date. Spot a cat stays easy to reach.

Empty: “Your Meowfolio is empty. The next cat you meet can be the first page.”

A cat’s page has its cover photo, prominent name, count, first/last-seen dates, and chronological history. Each encounter has its photo, date/time, optional note, and saved private location. No top-level cat note.

Check
  • A repeat updates the same cat’s count and history.
  • Reopening shows saved cats and sightings, subject to browser data retention.
  • No model metrics or coordinates on collection cards.
  • No editing, charting, badges, or complicated filters.
F7Outdoor proof and useful matching

Run the normal app loop on the learner’s Android phone/current Chrome. Windows Chrome helps development but does not replace phone evidence.

Controlled evaluation uses roughly 8–12 known cats and 40–60 photos, with varied conditions and visually similar cats. Fix the strategy and a single conservative threshold using development photos before inspecting independent held-out queries. Indoor photos do not prove outdoor usability. This dataset expansion was explicitly requested during technical planning.

Check
  • Separately show new save, repeat encounter, and persistence after reopening outdoors.
  • Report model execution separately from useful similarity results.
  • Manual repeat selection alone does not prove matching.
  • If separation fails, matching is unproven. Revisit with the learner.

Photography first. Everything else quiet.

Warm paper, dark readable text, natural greens, and a restrained terracotta accent. Large photographs, soft borders, subtle shadows, tactile cards, generous spacing, and minimal navigation.

Paper-like backgroundNatural greenWarm accent

Personal and handmade, modern and clean. Avoid generic AI gradients, neon, glassmorphism, dashboard styling, Pokémon-like imagery, excessive motion, and paw-icon clutter. Exact fonts and color tokens are for the technical plan.

Location stays quiet and private

In F6 encounter history, a subtle Location saved indicator sits beside the timestamp only when location exists. Opening it reveals that encounter’s stored latitude, longitude, and accuracy. Details stay collapsed by default.

Check: no invented place names, no map, and no external geocoding request. The saved local values are shown only on deliberate expansion.

Back is not discard

F5aScan-session recovery

During preparation or processing: stop active work where possible and return to photo preview. Keep the photo and any already cached model files. Processing can restart; late cancelled results must not advance the flow.

Back within identity/save steps: retain photo, entered name, encounter note, and captured location in memory. Returning to details restores them.

Cancel scan or leave for collection: when a photo or entered details would be lost, ask “Discard this encounter? Your photo and unsaved details will be lost.” Keep editing preserves the session. Discard encounter clears it and returns to the collection.

Check
  • Back preserves in-session inputs.
  • Discard creates no saved encounter.
  • No persistent unfinished drafts: close/reload may lose unsaved work.
  • Only successfully saved encounters become persistent scrapbook data.

Names belong to people; identity belongs to each cat

F5 requires a name that is non-empty after trimming leading/trailing whitespace and at most 40 characters. Unicode, non-English names, accents, symbols, and normal punctuation are allowed. No profanity filter or unnecessary restrictions.

Two cats can both be Mochi. Distinct internal identities keep their encounters separate. Photos, encounter counts, and first/last-seen dates distinguish same-name cats in the picker. Never add automatic suffixes.

Check: reject blank or overlength names; preserve valid Unicode; save two same-name cats without merging, overwriting, or renaming either.

Product approved

The product questions raised during review are resolved, and the learner has approved this PRD.

Before spec approval: define usable timing limits and reproducible similarity gates, informed by real-device measurements. Exact download size, availability checks, fallback, and retry implementation belong in that plan.

Keep the proof small

12–16 focused hours: risky real-device AI path first, then the complete loop, then usability/failures/privacy/outdoor testing, then polish.

Deferred additions

Other browsers, PWA/offline shell, maps, export/import, achievements, decorative polish, editing, statistics/charts, complex filters, and persistent “About this cat” descriptions.

Non-goals

Accounts, social networking, cloud inference/backend, public exact-location maps, automatic identity, AI names/biographies, other animals, and broader game mechanics.

Refinements to the earlier documents

Manual existing-cat selection is now required. Missing model files require download consent. Notes are encounter-specific only. Android Chrome is the release target, and the event remains the Hacktoberfest DEV Touch Grass challenge.
