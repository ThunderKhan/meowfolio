Where the work and data live

Follow one encounter

  1. Welcome and capture: browse without AI; select a photo and preview it.
  2. Check real assets: missing files require Download models & continue. Cached initialization does not require new consent.
  3. Detect: worker returns boxes; multiple cats pause for the person's subject choice.
  4. Embed and compare: selected crop becomes a normalized vector; incompatible references are excluded.
  5. Human decision: first-cat naming, conservative suggestion, or manual existing/new choice.
  6. Atomic save: stable encounter ID makes retries idempotent; compatible reference changes commit with the encounter.
  7. Return: cards and history read committed local data. Keep walking.

Explore the implementation boundaries

Each reveal maps back to PRD behavior and planned files. The Markdown contains the full annotated file tree and schema.

App and scan session · F1, F4–F6, F5a

src/App.tsx, src/scan/, src/ui/ own explicit scan states and in-memory inputs. Back preserves inputs. Replacing a photo invalidates old results and identity confirmation. Discard asks before losing meaningful work.

Names are trimmed, non-empty, Unicode-capable, at most 40 user-perceived characters, and not unique. A small History API adapter is proposed instead of a routing dependency. Save in flight cannot be presented as an encounter safely discarded.

Image preparation · F1, F3

src/browser/images.ts handles decoding, orientation, resizing, valid crop geometry and object-URL cleanup. Retain the source Blob in memory if transferring an ImageBitmap. Save a usable encounter photo and crop/geometry; never persist a temporary object URL.

Resize/encoding limits come from phone quality/memory measurements. Invalid input offers photo replacement.

Consent and cache · F2

src/ai/assets.ts and manifest.ts pin files and inspect actual cache entries. Guard the loader's network path as well as the cache pre-check. A missing entry after checking must fail closed, not silently download.

Cancel revokes authorization for new requests; abort ongoing requests only where verified. Completed cached files may remain. Audit runtime WASM/module and external ONNX data requests too: model fetch hooks alone do not prove every AI network path is controlled.

Decisive test: consent → cache → recreate worker with network blocked → remove an asset → verify no silent refetch, including removal between check and load.

Worker lifecycle and cancellation · F2, F3, F5a

src/ai/worker.ts, client.ts, and protocol.ts serialize model work. Detection and embedding are separate so subject selection can happen between them.

Messages include request/generation identifiers. UI invalidation is immediate; verified abort is best-effort; uninterruptible results are ignored. Terminate/recreate only for a stuck/broken worker, not normal Back. Never let old queued work acquire a newer download permit.

Spike: Android worker WebGPU and WASM, both model paths, progress, transfer, invalidation and second-scan reuse.

Models and embedding spaces · F2, F3, F7

src/ai/detector.ts and embedder.ts isolate model-specific tensors. YOLOv10n and DINOv2-small are starting candidates, not unchangeable dependencies.

Verify actual 384-dimensional output, pooling, preprocessing, dtype support and provider compatibility. Compare supported quantized and standard variants. The detector's reported AGPL-3.0 licensing must be resolved before release.

Space identity includes exact model/revision/artifact, preprocessing, dimension and output transformation version. Reject malformed vectors. No cross-space matching or silent migration.

Reference strategy · F4, F7

src/domain/embeddings.ts, matching.ts, and src/ai/matchingPolicy.ts normalize, check compatibility, rank and abstain.

Native IndexedDB and safe retries · F5, F6
src/storage/database.ts and repository.ts manage two stores, indexes and transactions. No database library or unique name constraint.
  1. Check stable encounter ID inside the transaction.
  2. If already committed, return the existing result; never add to the sum/count twice.
  3. Otherwise add encounter and update the latest cat record atomically.
  4. Wait for transaction completion before success.
Prepare images before the transaction. Abort rolls back both records. Failed saves retain session inputs. Cover initially points to the first encounter; no cover-editing feature is added.


Location and scrapbook · F5, F6
src/browser/location.ts is called only by Add location; ignore late callbacks after save-without-location or discard. A finite timeout still needs agreement.
Collection.tsx and CatDetail.tsx show image-first saved history. Encounter-only notes. Location saved expands locally stored coordinates/accuracy, with no maps or geocoder. A database read failure must not masquerade as an empty collection.

Two stores; distinct responsibilities

Cat

ID, name, dates, count, cover-encounter pointer, reference sum/count/vector and embedding space. No cat-level note.

Encounter

ID, cat ID, timestamp, photo/crop, individual embedding and space, detection metadata, optional note/location.

encounterCount = 5 and referenceEmbeddingCount = 3 is valid when two sightings use another embedding space. History is continuous; reference spaces remain isolated.

Warm-scan timing is a product gate

Elapsed timeBehavior
0–6 secondsTarget: initialized models, normal single-cat photo, full Find the cat → identity decision.
6–10 secondsTolerable for this PoC, but below the desired experience.
10 secondsShow Keep waiting / Cancel and go back. Keep waiting does not reset the deadline.
20 secondsInvalidate request and show retry/change-photo/back recovery. Late success cannot advance the UI.

Record download, cold initialization, cached initialization and warm per-stage timings separately for each provider. Human crop-choice time is separate. Routine warm scans above 10 seconds mean revisiting the approach.

Precision before recall

Release suggestions only with defensible evidence. Zero unresolved wrong suggestions in the final evaluated set, correct suggestions across multiple cats, and roughly half of true repeats as the practical target. Abstention is acceptable.

Use earlier confirmed references for later queries. Record correct-cat score, highest wrong-cat score and actual top-candidate outcome for first-only and centroid. One conservative threshold, no per-cat tuning.

Proposed validation hygiene: choose strategy/threshold on calibration photos, freeze, then evaluate untouched later photos. Retuning after a failure requires disclosure and new holdouts. The small trial is not general cat-recognition accuracy.

If neither strategy passes: ship the manual scrapbook only if chosen, keep suggestions disabled, and clearly state familiar-face matching is unproven.

Prove before polishing

  1. Pin candidates and inventory artifacts/licensing.
  2. Verify detector → crop → embedding in Chrome.
  3. Run the exact worker/provider paths on Android; measure and reuse models.
  4. Enforce consent under cache eviction and network-blocked initialization.
  5. Verify transaction rollback, retries, duplicate names and incompatible history.
  6. Run the chronological field trial and normal outdoor save/reopen loop.

src/spike/ exposes development-only measurements; docs/evidence/ records non-sensitive results. Final app UI stays focused on cats.

Two separate evidence sets

Controlled matching

Roughly 8–12 known cats, 40–60 photos, about 4–6 per cat. Include similar coats/patterns and varied angles, distances, poses and lighting.

Example: 10 × 5 gives 30 development/reference photos and 20 untouched held-out queries. Split independent capture groups, not near-duplicate bursts.

Actual Android/outdoor use

A smaller set captured through Meowfolio demonstrates camera → detector → embedding → human decision → save → reopen.

Indoor controlled photos do not establish outdoor usability. Report these results separately.

Held-out protocol and negative cases

Freeze the chosen strategy, threshold, preprocessing and development references before final evaluation. Score each held-out query without adding it to any reference. Log both first-only and centroid using development-fixed settings; choosing a new winner after viewing results requires fresh holdouts.

Report correct suggestions, abstentions, wrong suggestions, correct-cat similarity and highest competing similarity. For predeclared negative cases, exclude the query cat from the reference gallery and check abstention; report these separately, not as additional independent photos.

No threshold or artifact retuning on the final set without disclosing that it has become development data. Roughly half repeat recall is a practical target, and zero unresolved wrong suggestions remains the precision-first release goal.

Running it on Vercel

The app does not exist yet. Planned startup after scaffolding: npm ci, then npm run dev -- --host 127.0.0.1 --port 5173 --strictPort.

Static HTTPS host: Vercel. Connect GitHub, select Vite, production branch main, build command npm run build, output dist. No Functions, API, authentication or server database. Models still download from pinned Hugging Face assets after consent.

Use the stable production URL for Android/outdoor checks. Preview URLs have separate browser storage/cache environments and must not be swapped during persistence testing. Authorized ADB reverse to localhost remains optional for development.

Verify persistence across a frontend update
  1. Open the production URL and consent to model downloads.
  2. Process a real cat and save the encounter.
  3. Close/reopen; verify scrapbook and cached-model behavior.
  4. Deploy a frontend update to the same production origin.
  5. Verify existing IndexedDB records and images remain intact.

Frontend updates must not reset scrapbook storage. Model-cache changes are separate. No offline-shell or permanent-cache promise.

Resolve before spec approval
  • Agree download/cold-initialization recovery and location timeout.
  • Approve focused test tools: proposed Vitest plus real-Chrome integration checks; optional Playwright automation must not replace real Android inference evidence.
Evidence-gated spike outputs

Exact runtime/model versions, dtype/files, pooling, cache behavior, execution provider, image limits, download sizes, license resolution, and matching policy. These must be recorded before building around them, not guessed to finish a document.

Explicit refinements to older plans

Model choices are starting candidates. Manual-only release is permitted if suggestions cannot be validated, but does not prove the recurring-cat kernel. Reconcile these learner decisions with older context/architecture/evaluation documents when this plan is approved.
